NPC intelligence

More than a stateless chat endpoint

Three bounded systems work together so Innkeeper Liu can feel coherent without creating a permanent player profile.

01

Continuity

Session memory

Liu can refer back to details from the latest conversation instead of treating every message as a first meeting.

Implementation boundary

Keeps the latest 8 successful turns per browser session.

02

Relationship

Hidden affinity

Polite, trusting, or hostile language changes how warmly Liu responds and how willing he is to share sensitive clues.

Implementation boundary

Deterministic local rules; no extra model call and no visible relationship meter.

03

Resilience

Recoverable dialogue log

Refreshing the page restores the current conversation so the player can continue reading and asking questions.

Implementation boundary

Player and NPC messages stay in server memory—never files, a database, or browser storage.

System architecture

A protected path from input to character

The browser owns presentation and interaction. The server owns identity, session state, prompt context, limits, and model credentials.

  1. 01 Browser Keyboard, gamepad, dialogue UI
  2. 02 Three.js client World, animation, WebGPU/WebGL
  3. 03 FastAPI boundary Validation, origin checks, budgets
  4. 04 NPC session Memory, affinity, dialogue log
  5. 05 HelloAgents Bounded prompt and model adapter
Ephemeral session state

Isolated by browser session, capped at eight turns, expired after 30 minutes idle, and cleared whenever the service restarts.
